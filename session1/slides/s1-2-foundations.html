Session 1 · Core Concept

Agency ≠ Chatbots ≠ Workflows ≠ Prediction

Each one is a fundamentally different system.

System What it does Who acts Example
Chatbot Responds to input — no persistent state, no action taken Human reads, then decides GPT answering a product question
Workflow Fixed sequence, deterministic, no reasoning System executes a script Zapier automation, approval chain
Predictive AI Scores or classifies — outputs a number, doesn't act Human interprets, then decides Churn model, fraud score
Agentic AI Perceives, reasons, acts, learns — across multiple steps, with memory and tools System owns the outcome Autonomous CX resolution bot

Session 1 · Inflection Point

What Changed?

Each stage shifted where human judgment was required. Agentic AI is the first stage where the system can substitute for judgment — not just amplify it.

In every previous stage, a human still owned the outcome. Prediction gave you a score. Generative AI gave you a draft. You still had to decide what to do with it.

Agentic AI is different. The loop closes without you.

Session 1 · Definition

Agentic AI — Defined

"Agentic AI is a paradigm where AI systems don't just answer queries but act autonomously with goals, memory, reasoning, and the ability to take actions across tools, APIs, and workflows."

Reasoning

Multi-step thinking to decide "what to do next" — not just pattern matching on the input

Memory

Context retention beyond a single conversation — state that persists across interactions

Autonomy

Call tools and APIs without constant user intervention or approval at each step

Coordination

Single agent or multi-agent systems that collaborate to complete a shared goal

Session 1 · Clarity

What Agentic AI Is — And Isn't

✓ IS

  • Autonomous — runs without constant human input
  • Goal-driven — aligns actions to an objective
  • Persistent — maintains state across steps
  • Adaptive — adjusts based on what it observes

✗ IS NOT

  • A faster chatbot
  • A workflow with an LLM bolted on
  • A prediction model that outputs a score
  • Magic — it fails in specific, predictable ways
Session 1 · Case Study

Copilot vs. Refactoring Bot

Same LLM underneath. What changed?

GitHub Copilot

Suggests code — the developer owns the outcome. Accept, reject, or ignore. Human is in the loop at every keypress.

Refactoring Bot

Reads your repo, writes changes, opens PRs, merges them — the bot owns the outcome. You review after the fact, not before.

What changed: Autonomy + tool access + feedback loop.

The PM's job changes completely when the system owns outcomes rather than assists with them.

Session 1 · Critical Thinking

Agents Fail in Specific, Predictable Ways

Goal Misalignment

The agent optimizes for the proxy metric, not the real goal. Goodhart's Law at scale — when a measure becomes a target, it ceases to be a good measure.

Incomplete Observation

The agent acts on partial information and doesn't know what it doesn't know. No error message — just a wrong action taken confidently.

Cascading Actions

One wrong step compounds across the pipeline. In multi-agent systems, errors amplify before any human sees them.

PMs who don't spec failure modes are building systems that fail silently at scale.

The Architecture Loop

Or: Get the Mission → Scan the Scene → Think It Through → Take Action → Learn & Get Better

Perceive

Reads signals from the environment — tickets, APIs, databases, user input, prior state

Decide

Reasons over context — what does this signal mean, and what's the right next action?

Act

Executes — creates a record, calls an API, drafts a message, escalates to a human

Learn

Logs outcome — was the human's decision different from the AI's draft? That delta is a training signal

Session 1 · PM Implications

Where Does the PM's Job Sit?

For each architecture: where does human judgment sit? What does the PM own?

LLM Workflow

PM owns the prompt design and guardrails. Quality comes from how well you constrain the input. The LLM is a black box.

RAG

PM owns which sources the system retrieves from — and how fresh, curated, and scoped they are. Garbage in, garbage out at LLM scale.

AI Agent

PM owns tool permissions and the quality bar for autonomous action. What can the agent do without asking? Where must it stop and ask?

Agentic AI

PM owns the architecture: how agents communicate, where HITL sits, how the system is evaluated, and who is accountable when it goes wrong.

Session 1 · Environment Design

Agent Environments

Fully Observable vs. Partially Observable

Fully Observable

Agent can see everything it needs. Every field is present, every signal is available, no ambiguity about state.

Example: a structured database where all required fields are populated

Partially Observable

Agent works with incomplete information. Critical fields may be missing, ambiguous, or contradictory.

Example: a customer ticket with no order ID, vague product description

When the environment is partially observable, the PM must spec what the agent does when it can't see what it needs — that's a product decision, not an engineering one.

Wren Ticket B

Customer received the wrong product but has no order number. What should the agent do? This is a product spec question.

Session 1 · Human-in-the-Loop

HITL — Not Optional, Not an Afterthought

HITL-Always

Human approves every action before it executes. Safest — slowest. Right for high-stakes, low-volume decisions.

Medical triageLegal drafts

HITL-on-Threshold

Agent acts autonomously until confidence drops or risk exceeds a defined limit. Human steps in only at the boundary.

Fraud blockingCX escalation

HITL-Review

Agent acts fully autonomously. Human reviews audit logs after the fact. Fast — but highest trust in the system required.

Content taggingLow-risk routing

The PM chooses the HITL pattern. Engineering can implement any of the three — but only the PM knows which risk profile the business accepts.
