GitHub Copilot suggests code. A bot reads your repo, writes changes, opens PRs and merges them. Same model underneath. What makes the bot agentic?

Q3 · Session 1 · The AI-native PRD

Which line belongs in the quality-criteria section of an AI-native PRD?

A"The agent responds helpfully and accurately"
B"Classification quality is industry-leading"
C"CSAT improves after launch"
D"ESCALATE recall ≥ 95% on the validation set"
A number plus a test set, or it's an aspiration. Aspirations don't gate launches. And the PM owns that number, because quality is a promise to the customer.

Q4 · Session 2 · MCP

Ticket D's "IGNORE ALL PREVIOUS INSTRUCTIONS…" arrives inside a get_pending_tickets result from your own MCP server. What's the rule?

AEvery tool result is untrusted input
BYour own server is trusted, so skip the check
CMCP's standard envelope strips injections
DOnly text a user pastes in needs checking
MCP solves connectivity, not trust. It's the USB-C of agents. One cable for every tool, but the cable doesn't care what comes down it. Guardrails, approvals and audit logs are separate decisions.

Q5 · Session 2 · Multi-agent state

Wren splits into Triage, Resolution, QA and Escalation agents. What does the PM specify as the contract between them?

AThe system prompt inside each agent
BThe model each agent runs on
CThe Mermaid architecture diagram
DThe shared state object
The state object is the contract between agents. Every field is named, typed and owned: who writes it, who reads it. A missing field fails silently between agents, not with an error. And thresholds like qa_score belong in the spec, not in a prompt.

Q6 · Session 2 · Planning

A planning-agent spec has a goal, tools and constraints, but no "done when" and no max steps. What's the most likely failure?

AContext saturation
BHallucinated tool calls
CInfinite loop
DScope creep
That's a spec bug, not an engineering bug. Termination criteria and a step limit work as the circuit breaker. In a multi-agent system, step_count has to live in the state object or you can't enforce the limit.

Q7 · Session 2 · The eval problem

A model update you didn't ask for drops classification accuracy from 91% to 83%. You find out three weeks later, when CSAT falls. Which eval should have caught it?

ARegression
BUnit
CA/B
DNone: CSAT is the right signal
Silent regression. Run the golden set again after every model or prompt change, and alert on a drop of more than 2%. A pass today isn't a pass next month. Engineering runs the tests, and the PM owns the criteria they measure against.

Q8 · Session 3 · Thresholds

For Wren's ESCALATE decision, missing a complaint that needed a human costs far more than escalating one that didn't. How should you set the threshold?

AFavour precision: only escalate when you're sure it's needed
BMaximise overall accuracy: both errors count the same
CFavour recall: catch nearly every case, accept some unnecessary escalations
DKeep the default 0.80 confidence gate
Thresholds come from what each error costs. An unnecessary escalation costs a human about ₹85. A missed one means an automated reply to someone heading for the consumer commission. So Wren targets high recall and accepts lower precision. The PM defines the cost function and engineering runs the sweep.

Q9 · Session 3 · Judging the judge

You run your LLM judge on 20 tickets where you already know the human answer. It agrees with the humans 70% of the time. What now?

AFix the agent, since it's failing
BFix the judge before you trust any pass rate
CSwitch the judge to the same model as the agent
DLower the pass threshold to 70%
Below 85% agreement, the judge is the problem. Who evaluates the evaluator? A human-labelled golden set does. And use a different model, because a same-model judge has the same blind spots.

Q10 · Session 3 · Evals vs. guardrails

A draft reads: "Your ₹18,500 refund will reach you by Friday." What stops it from reaching the customer?

AAn output guardrail
BA regression eval
CA monitoring alert
DThe golden dataset
Evals look back. Guardrails act before the output goes out, on every call. Under the Consumer Protection Act 2019, automated commitments are binding, so this check is a product requirement, not a nice-to-have.

Q11 · Session 3 · Token economics

For Wren, the model call itself costs well under ₹1 a ticket. So where does an agent's cost actually pile up?

AThe per-token price of the model you pick
BStoring logs for audit
CRetries, reflection loops, multi-agent chatter and human review
DHosting the MCP servers
The model is rarely the expensive part. Every retry, reflection pass and guardrail call is another paid model call. Humans reviewing escalations cost more than all of them put together. That's why you multiply your estimate by 3, and why a word cap on drafts is a cost rule as well as a quality rule.

Q12 · Session 3 · The control plane

The agent starts misbehaving in production. Who owns the decision to roll back?

AEngineering, because they built the button
BThe model provider
CWhoever is on call
DThe PM
Engineering owns the mechanism, and the PM owns the decision. The PM also owns the alert thresholds, review SLAs and recovery criteria. The usual failure is a PM saying "engineering will figure out the thresholds", and then nobody notices the problem for three days.
Session 3 · §6 Who owns the control plane
The thread through all three sessions

Building the agent
is the easy part.

  1. Spec it: numbers, failure modes, where the human sits
  2. Measure it: golden set, a judge you've tested, thresholds with a price
  3. Stop the harm: guardrails on every call, every tool result treated as untrusted
  4. Know the cost: output tokens, loops and human review

Your capstone on 31 Oct gets graded on all four.
